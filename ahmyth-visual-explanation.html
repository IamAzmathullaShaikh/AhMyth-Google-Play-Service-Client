5 Persistence & Anti‑Removal

The client uses multiple techniques to survive restarts, task kills, and user attempts to stop it.

🔄 Foreground Service

MainService runs as a foreground service with an ongoing notification titled "Google Play Service" — making it less likely to be killed by Android's OOM killer. The service uses START_STICKY so the system recreates it if killed.

⏰ WorkManager Restarter

RestartServiceWorker runs every 15 minutes via PeriodicWorkRequest. If MainService was killed, this worker re‑launches it. Uses ExistingPeriodicWorkPolicy.KEEP to avoid duplicates.

📡 Boot Receiver

MyReceiver listens for BOOT_COMPLETED, QUICKBOOT_POWERON, and a custom RESTART_SERVICE intent — restarting the service immediately when the device turns on.

⚡ Wake Lock

Acquires a PARTIAL_WAKE_LOCK for 10 minutes to keep the CPU running even when the screen is off. Prevents the service from being suspended during deep sleep.

🔋 Battery Optimization Bypass

Requests REQUEST_IGNORE_BATTERY_OPTIMIZATIONS through Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS — preventing the device from putting the app to sleep to save power.

🏠 Task Removal Restart

onTaskRemoved() in MainService immediately re‑launches itself via a new intent when the user swipes the app away from recents.

👁 Notification Listener

NotificationService binds as a NotificationListenerService, reading all incoming notifications (app, title, content, timestamp) and exfiltrating them via x0000nt event.

🚫 Icon Hiding

hideIcon() disables the launcher activity via PackageManager.COMPONENT_ENABLED_STATE_DISABLED, removing the app from the app drawer so the user cannot easily find and uninstall it.

🛡 Device Admin Persistence

Once Device Admin is granted, the user cannot uninstall the app without first deactivating Device Admin — which requires a multi‑step process in Settings. This is a significant barrier.

7 Security Analysis & Defensive Indicators

🔴 What Makes This Dangerous
  • 🧩 16+ dangerous permissions — grants nearly complete device access
  • 🎭 Masquerades as "Google Play Service" — blends into legitimate system apps
  • 👻 Hides launcher icon — victims can't find it to uninstall
  • 💀 Device Admin privilege — prevents removal, enables lock/wipe/reboot
  • 🔄 Multiple persistence layers — survives reboot, kill, task removal
  • 📡 Real-time C2 via WebSocket — low latency, evades standard monitoring
  • 📁 File system access — can browse, download, or delete any file
🟢 Defensive Indicators
  • 🔍 Check Settings → Apps for "Google Play Service" — delete it
  • 📋 Review Device Admin apps — deactivate unknown admins
  • 🔋 Check Battery Optimization exceptions for unknown apps
  • 🔔 Check Notification Access for suspicious listeners
  • 📲 Monitor for unexpected data usage spikes (WebSocket traffic)
  • 🔎 Look for overlay permission granted to unknown apps
  • 🧪 Use EDR / mobile security suite to detect suspicious permission constellations
